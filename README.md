# 事件模式平台

三个协作模块：**模式注册**、**事件接入**、**消费者投影**。

## 模块

| 模块 | 文件 | 职责 |
|---|---|---|
| 模式注册 | `event_platform/registry.py` | 版本管理、管理员提案、发布/回退，发布前检查所有仍活跃消费者 |
| 事件接入 | `event_platform/ingestion.py` | 按声明版本验证事件、入库、隔离无效事件、触发投影 |
| 消费者投影 | `event_platform/consumers.py` | 消费者固定字段 ID 与类型、按各自视图生成投影 |
| 门面 | `event_platform/platform.py` | 三模块共享一把锁，跨模块操作原子完成 |

## 核心规则

- **字段身份 = 稳定数字 ID**；显示名称可重命名，不影响身份，投影以 ID 为键。
- 模式限定每个字段的**类型、是否必需、默认值**（`Field`）。
- 生产者按**声明的版本**提交事件，按该版本验证（不是当前可见版本）；
  发布新版本不弃用旧版本 —— 过渡期内新旧生产者都能提交有效事件，
  直到管理员显式 `deprecate`。
- 消费者注册/升级时固定 `{字段 ID: 类型}`，校验范围是**所有仍接受写入的版本**，
  不只是当前可见版本。
- **过渡期一致性闸门**（发布 / 回退 / 消费者注册与升级共用同一谓词）：
  切换或固定之后，每个仍接受写入版本的有效事件，都必须能为每个活跃消费者生成
  与其固定类型相符的投影 ——
  - 删除仍被固定的字段、跨版本类型漂移：拒绝；
  - 可见版本中的**必需**字段在任一接受写入版本中缺失或非必需：拒绝
    （否则旧版有效事件会投影出与声明类型矛盾的空值）；
  - 带默认值的可选字段：允许，旧版事件缺字段时接入侧用**可见版本默认值**补齐；
  - 无默认值的可选字段：允许，缺字段投影为 `None`（"可选即缺席"语义）。
- 发布/回退前检查所有仍活跃消费者；可见版本指针原子切换，失败不留中间状态。
- 无效事件进入隔离区；投影先为全部消费者构建完毕再与入库一次提交，
  不留部分投影。投影解析对"必需字段无法补齐"的不一致状态有防御性兜底：
  隔离事件，绝不入库矛盾投影。

## 运行测试

```bash
python3 -m unittest discover -s tests -v
```

`tests/test_event_platform.py` 中的 `InterleavedScenarioTest` 交错执行
发布新版 → 旧版写入 → 消费者升级 → 失败的发布/回退 → 成功回退，
逐步核对各方看到的版本与数据。
